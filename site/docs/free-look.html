PC vertical aiming

The playable Windows frontend consumes both axes of captured relative mouse input. Moving the mouse up looks up. Sensitivity is the existing 64 angle units per count (65536 per turn). Pitch accumulates without wrapping and is limited to +/-14564 units, approximately 80 degrees. Focus loss, paused/disabled input, and repeated sampling consume pending deltas without applying stale motion. Movement stays on the horizontal plane. H and jump retain their existing rules.

The first vertical input enables direct weapon aiming, replacing the original vertical target search and adjacent-yaw retries. Hitscan uses full yaw precision, the live eye height and tan(pitch), checking floors and ceilings before later wall/entity hits. Projectile muzzle placement and slope follow the same aim. The crosshair uses the original type18 HUD object in both views, including its original placement, target animation and weapon/death/automap visibility rules. The temporary custom projected crosshair has been removed. Level restart resets pitch and restores the initial aiming policy. The explicit original renderer option retains the horizontal GBA reference and ignores mouse Y.

GBA mode now follows the selected auto-aim slope with the original type18 cursor. SsaNativeGame.gba_view is bound at level initialization and when Settings changes renderer. A GBA tick clears software pitch/free-aim and consumes pending vertical input, so switching from software restores the original target search. Mouse Y still does not position the GBA cursor manually.

The HUD controller preserves original visibility and target animation, then projects the exact weapon-ray contact from the current level camera with view bob removed from the cursor's eye height. Original camera calculations run on copies with horizontal velocity zero and eye recovery disabled, retaining lowering, stair adjustment and height clamps without advancing simulation twice. The world/weapon view keeps its normal bob. Jump height and the chase-camera offset still contribute to cursor placement. This uses the original actor reciprocal-distance table and vertical projection, including the120-to160 display scale. The collision-checked chase position therefore lowers the cursor according to actual camera height, boom length and contact distance. Cursor placement is limited to visible screen edges. This read-only query uses the dedicated camera workspace, leaving gameplay traces intact. Software crosshair placement stays centered. NETRICSA's filtered OAM remains honored because reference drawing does not rebuild HUD sprites.

pc_renderer_pitch.inc adds world-space camera rotation to the dynamic PC renderer. Walls and upright directional actor billboards use near-clipped triangles with reciprocal-depth interpolation of texture coordinates and depth. Subsector planes are reconstructed once by clipping map bounds against BSP partitions and directed subsector wall halfplanes, closing implicit subsector edges. A topology fingerprint invalidates the cache on actual geometry changes; sector heights and colors are read live. Flat sky lookup storage is cached by resolution; column indices follow yaw and row indices follow pitch every frame. Triangle rasterization walks covered scanline spans and increments perspective attributes across each span. Live sector heights preserve moving doors. The sky remains perpendicular to the view, with horizontal panorama scrolling and vertical translation following the projected horizon. Pitch zero retains the prior column renderer; nonzero pitch uses geometry rasterization. Both paths retain the current vertical field of view and automatic resolution.
