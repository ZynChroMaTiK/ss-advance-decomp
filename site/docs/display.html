Native original-resolution display composition

src/display.c presents the native world/actor renderer's120x120 indexed framebuffer and native sprite OAM as240x160 RGB555 pixels. It executes no ROM instructions. Its input palettes and physical OBJ tile memory remain explicit, so palette animation, cache transfer order and HUD construction are not silently replaced. ssa_display_rgb888 optionally produces host0x00RRGGBB pixels by replicating five-bit channels; this is a host color conversion, not LCD calibration.

Original display evidence

Normal gameplay uses a tiled affine background, not a bitmap mode:

DISPCNT1441 selects mode1, BG2, OBJ and one-dimensional OBJ mapping. BG2CNT selects priority1, a256x256 wrapping affine map at06000000 and character bank1 or2. Tile number for world tile(tx,ty) is15*tx+ty. The map's extra column references cleared tiles; remaining map cells use cleared tile255.

The resulting normal sample is world[floor(3*y/4)][floor(x/2)] across the entire240x160 display. Horizontal pixels double; vertical output repeats one source row in each group of three. A square120x120 host viewport therefore does not preserve the original display aspect. General signed affine parameters are supported against this recovered map layout, including wrapping and the cleared area beyond120x120. This does not recover the code that changes those parameters for other effects.

Automap takes a separate mode4 branch in0750C and is rejected by this compositor. 0750C also performs palette/status updates; the register oracle executes them, but this module receives the resulting palettes rather than implementing their gameplay state machine.

OBJ rules and bounded scope

The compositor consumes all128 native SsaSpriteOam.entries, including their interleaved matrix words, and32768 bytes of physical OBJ memory. It supports normal8bpp one-dimensional tiled objects, transparent index0, horizontal/vertical flips, affine matrices and double-size bounds, signed/wrapped positions, and tile-address wrap. Matrix sampling uses the object/bounding-box centers with eight fractional bits. Sprite palette selection remains separate from BG colors.

Hardware references are the original author's GBATEK GBA documentation and the implementation's mGBA OBJ renderer. GBATEK documents OBJ winning equal BG priority, transparent color0, affine centers, and unusual conflicts when OAM and BG priority orders disagree. Mixed priorities now render instead of returning-2. The reduction follows the normal8bpp OBJ path in mGBA's software renderer: equal priority keeps the earlier OAM sample; a later higher-priority opaque sample replaces it. A transparent higher-priority sample preserves an already occupied pixel's color but promotes its priority. Empty pixels stay empty, and affine samples outside the source rectangle do not promote anything. The resulting single OBJ layer is then compared with BG2. Sorting sprites by priority or simply ignoring transparent samples would lose this behavior. The original unmasked tile-number overflow can alter priority bits, so it must not turn an otherwise valid frame into a native presentation error. These rules are a hardware-model implementation, not a new exact byte match or a physical GBA measurement.

Physical OBJ06018000..0601FFFF mirrors06010000..06017FFF in normal mode1. GBATEK's Memory Mirrors section and mGBA's VRAM store implementation establish this mapping. Cache transfers must apply the mirror before presentation; passing an independent64KiB logical window would incorrectly retain overwritten data.

Unsupported display modes/layers, windows, blending/semitransparent objects, nontrivial mosaic and4bpp objects return-2. A conservative scanline cost check also returns-2 when the frame might exceed the hardware budget. It includes the complete128-entry scan, offscreen-X objects and un-clipped affine bounding boxes; it does not approximate hardware pixel dropout. Actual FCE4 pieces have no mosaic-enable bit. Unsupported cases remain explicit even when their output might happen to look similar.

Invalid inputs return-1. Both errors occur before any output writes. Output must not overlap input registers, palettes, OAM, tiles or framebuffer; the API checks those spans. No pointers survive the call. The function has no mutable shared context, and rejects OAM while it is being updated.
