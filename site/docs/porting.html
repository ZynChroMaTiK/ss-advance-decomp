Established input behavior

ROM address Behavior Native implementation
0x08003028 Read active-low KEYINPUT; held/newly pressed edges; reset chord; record/playback selection ssa_input_poll
0x08003150 Pack buttons into one byte and append while count <= 0xE0E ssa_input_record
0x08003298 Expand packed buttons; advance repeat count and RLE stream; 0xFF ends playback ssa_input_playback

These three behavioral ports passed 14,848 differential cases against the supplied ROM's original instructions. The test includes all 1,024 physical button masks, simultaneous opposite directions, all 256 packed values, recording bounds, repeat-count bounds, record/playback priority, state flag gating and reset calls. It does not establish correct full-game integration, rendering or mouse controls.

The input state starts at 0x030042F0:

Offset Observed use
+0x00 Raw held (low halfword), pressed edges (high halfword)
+0x04 Processed held/pressed after recording/playback selection
+0x08 Saved global value during record/playback setup; broader purpose unresolved
+0x0C Recording-buffer pointer
+0x10 Playback-stream pointer
+0x14 Game-state value, not recovered here
+0x1E Recording position
+0x20 Remaining repeat count
+0x21 Current packed playback buttons
+0x22 Reset-related byte cleared when reset chord is absent
+0x23 Bit 1 records; bit 2 plays back; recording has priority

0x03004010 holds a pointer to another object. Bit 0 of its halfword at offset 4 suspends recording/playback. Its broader game-state meaning is not established. The native API calls this input_suspended.

The original recorder resolves simultaneous left/right to left and up/down to up. Select and Start are not encoded in recordings. Playback emits the current buttons before consuming the next run. Raw hardware polling retains the upper six bits of the inverted halfword; masking them early changes reset detection. Native pointers deliberately have host width; the native structure is not a binary-compatible GBA RAM structure.

Matching status and tool fixes

The manual recorder candidate is 97.5% similar, with the remaining differences at the initial global-pointer/limit/load scheduling. It is not counted among the 74 exact matches. Its best source and notes are stored in decomp.wtf.

The matched catalogue contains 2,152 bytes of verified C out of 87,648 imported function bytes. This denominator excludes undiscovered code. The 8 MiB image size is mostly data and is not a useful code-completion denominator.

Luvdis needed bounded-stack fixes for speculative paths, conservative handling of partial BL instructions it cannot model, and buffered output for WSL. scripts/test_luvdis_stack.py verifies large frames, negative stack positions, ordinary returns and unsupported partial calls. These changes do not modify the ROM. The initial 525-function catalogue was retained after an aggressive additional sweep proposed thousands of unverified starts.

The GBA exporter emitted unresolved Thumb-call labels as untyped absolute linker symbols. GNU ld inserted interworking veneers, overflowing the fixed ROM layout. The local patch emits typed absolute Thumb function symbols in a separate object. The exporter also now discovers unresolved canonical address symbols from C objects, including uncatalogued calls and IWRAM data references. Thumb-call relocations determine function mode; ordinary ARM calls retain ARM mode. This fix is recorded in patches/decomp-wtf-c-externals.patch and applied by bootstrap after the existing Thumb-symbol patch. tests/test_export_c_externals.py checks both patches against the pinned upstream and links real ELF objects to verify symbol types, data addresses and absence of added interworking veneers. The full rebuilt image is checked against the original. Unmatched code remains assembly or original data; the rebuild is not evidence of a complete decompilation.
