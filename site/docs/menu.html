Original startup menus

Main now has Single Player, Multi Player, Options, Scores and a PC-only Quit row, in that order. Rows start at74 with16-pixel spacing, so the fifth row stays on the160-pixel canvas. Quit is localized as Quit/Beenden/Quitter and supports keyboard and mouse. Selecting Quit opens a localized Yes/No warning with No selected by default. Enter on No or Esc returns to Main with Quit selected; only explicitly confirming Yes sets the separate quit_requested result. It never enters the new-game/level handoff; the host leaves its loop and uses normal cleanup.

Pause-menu Quit still asks Yes/No, then returns to Main. The frontend records the current game counter on every menu entry and checks that it stays frozen. The old startup-only counter-zero check incorrectly rejected a return from gameplay on the next tick, closing the window. Native menu checks now pass73072 assertions; Windows verifies12pause paths, six Main-menu Quit paths and six completion routes in both renderers and all3languages, including40menu ticks after each pause return. The settled menu rows and hover/click regions share the same positions; the menu startup/credits/options/map/restart check also passes. The current quit warning tests cover all3languages, keyboard/mouse Yes/No, default-No confirmation, Esc from Yes and blank-area clicks. Previews are at build/intermission-tests/quit-confirmation-0.bmp and quit-confirmation-1.bmp. See menu-validation.json, quit-confirmation-validation.json and the earlier windows-intermission-validation.json.

play-native.cmd now begins directly with the title prompt, main menu, Single Player, New Game and difficulty selection. All three languages and difficulty tiers work. Arrows/WASD navigate, Enter/Space confirms, or hover and click a menu entry. Mouse hit testing follows the localized text and sliding animation, with the same letterbox transform as rendering. Blank space and black borders cannot activate the current selection. Hover only changes selection when the pointer moves, so it does not override keyboard navigation. The Win32 pointer adapter now immediately plays original menu command12 (sound1) when hover or a direct click changes selection, matching keyboard cycling. Same-row movement, leaving into blank space and returning, and clicking the already selected row do not replay that cue. Confirmation retains its separate existing sound. The cue is delivered at the pointer event because the following menu tick clears its command queue. This applies to all shared menu hit targets; the portable menu state machine and original keyboard behavior are unchanged. Title/menu music continues across Press Start and returning to Main. Single Player now inserts Select Level between New Game and Password. It uses the original localized campaign names, saved previous-level completion unlocks, and no multiplayer maps. Options → Clear Data confirms Yes/No before resetting progress and language. Full behavior/storage/tests are in profile.md. Options has five rows: Settings, Extras, localized Language, Clear Data, and Credits. Keyboard and mouse follow that visible order; Credits is last. Internal IDs remain stable for existing Settings/Clear Data return paths. The row removal and reordering are requested PC UI changes; historical original Options-callback comparisons below describe the earlier layout, not this five-row screen. Extras holds Jump (moved from Settings), Third-person, and In-game NETRICSA toggles. Jump defaults to Off; Third-person and In-game NETRICSA default to On. They persist in settings.dat and accept keyboard or mouse changes. Disabling in-game NETRICSA leaves pre-level briefings enabled. See Settings and Extras. Enter, click or Right cycles English/German/French in place; Left cycles backward, wrapping at either end. All menu labels change immediately. The chosen language carries into maps, new games, password starts and R restart. Fresh profiles default to English; subsequent launches restore the saved language. The dedicated language list is no longer part of startup or reachable through Options. Esc goes back. The redundant Music On/Off row is removed; Settings provides the music volume slider (0% silences music) and sound volume/music style controls. Preferences persist through maps, level advancement and restart. M remains a separate PC mute control. Options → Credits now shows the original credits. Hold Up/W to pause or Down/S to scroll faster; Enter/Space/click or Esc returns to Options. An explicit --level 0..7 launch bypasses startup menus for diagnostics. Single Player → Password supports direct case-insensitive keyboard typing. The first typed character replaces the original A_______ template. Backspace, Delete, Home/End and Left/Right edit the bounded eight-character field. Enter or a click submits; letters including WASD/M type rather than navigating/muting. The original editor is also retained. Left/Right changes the selected character and Up/Down cycles letters, digits and underscore. Holding Up/Down repeats after the original delay; Enter/click submits and Esc goes back. A valid password supplies difficulty and starting weapon/ammo inventory. The frontend supports the eight admitted maps; valid later-map passwords display an unavailable-level notice and stay in the editor.

The menus use original artwork, glyphs, metrics, colors and localized strings. The green background scrolls in the original steps; the logo slides into place. The original transparent BG1 grid tile at080AAEEC now overlays the scrolling stone layer from the first title/main-menu visit. The grid stays fixed while the stone scrolls, and sits behind text and logo. Original cold startup enabled BG0+OBJ only (1141), while subsequent menu entries enabled BG1 too (1341); the user's requested PC behavior shows the grid on startup as well. The port previously omitted BG1 entirely. The title prompt observes its original90-frame input gate and blinking rule. Main-menu entries slide in from alternating sides. New Game uses the original screen/audio fade before the pre-level map. No gameplay simulation runs during either menus or map. The map music remains confined to the map, and the level soundtrack starts when gameplay begins.

Difficulty selects the already recovered combat damage rules: easy halves incoming enemy damage and increases outgoing damage; normal applies its original two-thirds incoming scaling; hard increases incoming damage and reduces outgoing damage. The chosen difficulty and language persist on level advancement and R restart. Initial continue values5/3/2 are selected, but the original continue screens and finite continue progression are not implemented yet. R still follows the documented PC checkpoint policy. Language affects menus and map screens; existing simple host gameplay notices remain English.

Recovery and boundaries

The Main-menu Scores destination now runs the original1737C viewer natively. It displays the18 original seeded entries in three localized groups, with the original scrolling, arrow blink, fonts and colors. Arrow keys and mouse arrows change group; Enter/Esc or a center click leaves. Original16F70 ranking and16F98 name entry now connect Quit-run/campaign-ending records, keyboard typing and the separate scores.dat file. See scores.md.

src/menu.c reconstructs the1862C outer loop and page callbacks16A34 (main), 17BBC (language),17CD0 (title),17DB8 (difficulty),17F7C (single-player) and180D4 (music/credits options), plus179DC (credits) and16BE4 (password). It preserves input ordering, edge navigation, selection clamps, sound commands, state markers, title counter reset and the final fade boundary. Rendering uses the same shared ROM font/palette canvas as map_view.c. Title-first startup and inline Language are requested PC changes to the original flow. The recovered Language handler remains available only to recovery fixtures. The first Title tick starts menu music; Press Start preserves sequence position. It retains the old page's final submitted frame when an input changes pages, as the original callback does. The background uses tiles0A8368 and the original 64x64 tilemap construction; the logo's three64x64 sprites use0B5434. No ROM CPU instructions execute in the port.

Frontend pages are0,1,4,8,9,11,12; page10 is a recovery-only diagnostic. Multiplayer and scores remain unfinished. Their entries give a clear unavailable notice and keep the current menu usable. These guarded destinations are PC prototype boundaries, not recovered original behavior or completed features. Publisher/boot screens, remaining menu pages also remain. Pause Continue/Quit/Yes/No now connects to the frontend, alongside persistent saved options and original chapter panels; see pause and completion. The full game is not claimed feature-identical by this milestone.

Thus the startup grid is an explicit PC addition to the original cold-boot display state, with exact original artwork and priority, rather than a claim of identical cold-boot pixels. A first-visit native check proves transparent grid holes retain the stone background and nonzero grid samples replace it before any gameplay. Malformed grid data is rejected at initialization. The current title-first/inline-language tests pass70,367 checks over9,242 frames and18 new games under ASan/UBSan/leak detection. Credits include2,670 compared frames and three complete scrolls, all89 source lines/88 newline advances, entry/re-entry, Up/Down priority, acceleration and release, manual confirm/back, and automatic return. String246 currently resolves to the same original ROM data for all three languages. The0.5-pixel/tick scroll becomes2 pixels while Down is held; Up takes precedence and freezes it. Extra draws do not advance scroll or input.

ssa_menu_step_input separates held keys from pressed edges; the existing step entry remains available. The Win32 adapter tracks Up/W and Down/S separately, including simultaneous alternate keys, key releases, and focus-loss clearing. ROM text is bounded; lines that would overflow the original32-byte stack buffer are rejected in the native port.

Password coverage adds4,830 ROM frames: all36 table matches and complete fades, all three languages, cursor wrap/highlight, invalid submission, character cycles, hold repeat and byte-counter overflow. Up/Down counters wrap255 back to32; repeat requires counter>30 and a multiple of4. Down takes priority. Right/Left wrap the eight-position cursor; Right takes priority. The editor starts at A_______. The original measures password width with spacing0 but draws with spacing1; the selected character is submitted first in palette1, then the complete string in palette2, preserving OAM priority. The default library level limit is12; the frontend sets9, guarding later-map passwords before fading or changing state.

One original data quirk is table entry12, the seven-character MEDIUM_. The eight-character cycling editor cannot produce that terminating NUL. The ROM comparison supplies this memory state explicitly to validate the original match; The new PC typing path accepts it directly, while the original cycling path and its independent ROM comparison retain the original behavior.

Typed password submission now ignores trailing underscore placeholders on both the entered text and ROM code. The display already pads a short typed field to eight slots; validation previously compared the shorter NUL-terminated buffer against the ROM's underscore-filled string, incorrectly rejecting ordinary words until arrow editing materialized the padding. EASY, EASY_ and EASY____ now select the same entry directly. MEDIUM, MEDIUM_ and MEDIUM__ also work despite the ROM's seven-byte entry. Internal underscores, wrong characters and incomplete words remain invalid. Cursor/editing state is not changed by normalization. The original arrow-only comparison still uses exact ROM matching.
