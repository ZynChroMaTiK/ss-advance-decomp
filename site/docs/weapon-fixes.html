Continuous weapon audio and ballistic PC rockets/Prion shots

The native host now owns the local continuous weapon voice explicitly. Original minigun wind-down (sound 0x1A) stops firing loop 0x19 before playing its ending; chainsaw 0x13 similarly stops 0x12. The original controller assumed the shared GBA hardware voice would replace the prior sound. Independent native effect instances require this explicit cleanup. Machine gun loop 0x16 shares the same lifetime tracking.

After each simulation frame the host checks firing, weapon handoff, ammunition, focus, input enablement, pause, health and gameplay music state. It stops a stale local loop without stopping other sources or music. Unbinding audio also stops the tracked loop. Source-aware sinks use local identity 1; legacy sinks retain the play/stop callback contract. Wind-down cues remain audible. This changes presentation ownership, not original firing cadence or the recovered controller.

The PC composition opts into SsaProjectileRuntime.ballistic_player_rockets. Committing a player type-65 rocket clears original attachment flag 0x4000 immediately. Its constructed position and full XYZ velocity now remain independent of subsequent player view/movement from launch. Owner exclusion flag 0x100 and player index remain intact. Enemy rockets and unlimited player range retain their existing behavior. The default recovery runtime leaves the option zero, preserving the original motion oracle and its attachment quirk.

The PC composition also enables ballistic_player_prion for weapon7/type69. Commit clears its attachment flag immediately, retaining owner exclusion, source, speed, conversion impact and lifetime handling. Creation removes the original40-unit sideways offset and uses the actual full player heading even when the original level-aim no-target probes finish at heading-512. The192-unit forward launch distance is projected along pitch, with Z measured from the live eye plus the aiming slope, so the projectile starts on the sight line. This works before any vertical mouse input as well as with free vertical aim. The recovered controller's target/slope selection is retained; this changes the native PC launch adapter, not the standalone recovered routines. Default recovery runtime options remain zero. No new speed or conversion rules are added.

A changed rocket combat route exposed an existing reference-renderer boundary: a portal upper wall ending exactly at y=120 requested an offscreen row. The native column helper can now discard that single trailing row while retaining the full original sampling count. Shortening count would apply the original final-pixel correction to a visible pixel incorrectly. Ordinary raster bounds remain strict. Scene storage layout and framebuffer size are unchanged.
